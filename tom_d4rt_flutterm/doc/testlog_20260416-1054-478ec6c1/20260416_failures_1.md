## Executive Summary

The 10 failures cluster into **3 distinct root causes**:

| Cause | Count | Failures |
|---|---:|---|
| **AST generator bug** — `ForEachPartsWithPattern` (Dart 3 record destructuring in for-loops) not handled in `ast_converter.dart` | 7 | 1, 4, 6, 7, 8, 9, 10 |
| **Script bug** — demo imports `package:flutter_test/flutter_test.dart` and uses `testWidgets` / `WidgetTester` / `expect` / `find`, which violates the "single stateless `build(BuildContext)`" demo convention | 2 | 2, 5 |
| **Missing script file** — the `.dart` the test references does not exist on disk | 1 | 3 |

The AST-generator bug is the single biggest blocker: fixing it in one place in `tom_ast_generator` will unblock all 7 failures in this batch (and almost certainly many more across the full suite, since record-destructuring for-loops are a natural idiom for the deep-demo gallery sections).

## 1. dart_ui/point_mode_test.dart

**Category:** AST generator bug — record-pattern for-loop not converted
**Source file:** `hardly_relevant_classes_1_test.dart`

### 1) Code causing the problem

[test/tom_d4rt_flutterm_app/test/send_ast_via_http_scripts/dart_ui/point_mode_test.dart:719](../../test/tom_d4rt_flutterm_app/test/send_ast_via_http_scripts/dart_ui/point_mode_test.dart#L719)

```dart
for (final (i, label) in ['points', 'lines', 'polygon'].indexed) {
  // ...
}
```

The loop uses a **record pattern** (`(i, label)`) in the for-each declaration. Analyzer produces this as an `analyzer.ForEachPartsWithPattern` AST node.

### 2) How it can be fixed

**In the AST generator** at [tom_ast_generator/lib/src/converter/ast_converter.dart:231-234](../../../../../../../tom_ast_generator/lib/src/converter/ast_converter.dart#L231-L234):

```dart
// Currently handled:
if (node is analyzer.ForEachPartsWithDeclaration) return _convertForEachPartsWithDeclaration(node);
if (node is analyzer.ForEachPartsWithIdentifier) return _convertForEachPartsWithIdentifier(node);

// Missing — Dart 3.0 record-pattern for-each:
if (node is analyzer.ForEachPartsWithPattern)   return _convertForEachPartsWithPattern(node);
// Also missing — Dart 3.0 pattern-declaring classic for:
if (node is analyzer.ForPartsWithPattern)       return _convertForPartsWithPattern(node);
```

A new `SForEachPartsWithPattern` class (parallel to the existing `SForEachPartsWithDeclaration`) must be added in `tom_ast_model/lib/src/ast/ast_statements.dart`, carrying the `SDartPattern` plus the iterable, and the interpreter's for-loop executor needs to destructure the pattern against each iterated value.

### 3) Root-cause classification

**Generator problem** (AST converter in `tom_ast_generator`). The demo code is valid Dart 3 — the interpreter/generator pipeline has not caught up to the language spec.

### Error

```
type '_SUnknownNode' is not a subtype of type 'SForLoopParts?' in type cast
```

The converter falls through to `_SUnknownNode` (line 320) because no branch matches `ForEachPartsWithPattern`; then `SForStatement` fails the `as SForLoopParts?` cast.

## Recommended Actions

### Highest-leverage fix — 1 change unblocks 7 tests in this batch

**Add `ForEachPartsWithPattern` support to the AST generator.** Concretely:

1. **`tom_ast_model/lib/src/ast/ast_statements.dart`** — add a new node class:
   ```dart
   class SForEachPartsWithPattern extends SForLoopParts {
     final SDartPattern pattern;   // the (x, y, z) record pattern
     final SExpression iterable;
     final SToken? keyword;        // final / var
     // ... constructor, accept(), etc.
   }
   ```
   Add a parallel `SForPartsWithPattern` for pattern-declaring classic for-loops.

2. **`tom_ast_generator/lib/src/converter/ast_converter.dart`** — around line 234, register the new analyzer node types:
   ```dart
   if (node is analyzer.ForEachPartsWithPattern)
     return _convertForEachPartsWithPattern(node);
   if (node is analyzer.ForPartsWithPattern)
     return _convertForPartsWithPattern(node);
   ```
   Implement `_convertForEachPartsWithPattern` to build the new `SForEachPartsWithPattern` with the record-pattern already converted via the existing pattern-conversion path.

3. **Interpreter (d4rt)** — update the for-each executor to branch on `SForEachPartsWithPattern`: obtain each iterated element, destructure against the record pattern's fields, bind them into the loop's local scope.

4. **Regenerate bridges / AST model** per the project's regen workflow.

### Script-level follow-ups

- Rewrite `material/list_tile_style_test.dart` and `rendering/diagnostics_debug_creator_test.dart` as stateless deep demos (remove `flutter_test`).
- Create the missing `painting/asset_bundle_image_provider_test.dart` demo, or mark the test skipped until authored.

### Optional short-term workaround (no interpreter change)

Sweep the 7 affected demos and replace each record-pattern for-loop with explicit positional-field access (`r.$1`, `r.$2`, …). This unblocks the tests immediately but does not fix the underlying d4rt limitation.
