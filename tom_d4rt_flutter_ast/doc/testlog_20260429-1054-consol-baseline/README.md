## Notes on the numbers

- The 15× `D4rtTester end-to-end dcli_scripting_guide` cluster
  appears in both `tom_d4rt_exec` and `tom_d4rt_generator` — it's
  the same dcli scripting guide suite mounted in two places. Any
  fix lands in one canonical d4rt-tester implementation; both
  projects' verdicts will move together.
- The callback-wrapping failures (`G-CB-7/11/12`) and
  `DCL-CLS-002` show in `tom_ast_generator` and `tom_d4rt_exec`
  for the same reason (shared codegen path).
- `tom_d4rt_ast` shows two errors in `ast_module_loader_test` —
  the stdlib loading path is the very thing the consolidation
  plan plans to expand. Treat these as a known starting point;
  do not regress them further.
- `tom_d4rt` v1.8.1 baseline is documented as 1680 tests with 2
  pre-existing failures. The number we capture (1728/5/1) is
  higher because the suite has grown since v1.8.1.
- Two project test suites (`tom_d4rt_generator`,
  `tom_ast_generator`) needed `pubspec_overrides.yaml`
  activation before tests would resolve dependencies. Both now
  have `pubspec_overrides.yaml` files committed (copies of the
  canonical `pubspec_overrides.dev.yaml`) — see the
  consolidation-plan baseline commit.
